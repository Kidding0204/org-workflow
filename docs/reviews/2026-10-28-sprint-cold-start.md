# Sprint 首次打开耗时与有界扫描

基线 d390c0e。目标是定位首次打开的剩余成本，只保留收益明确、维护成本低的改动。
包开始时干净；父配置已有修改保留。本轮没有改写真实 Org、SQLite 或历史快照。

## 首次打开的成本

在隔离 profile 中启用 Workflow，通过原生 org-agenda "d" 打开 4 个尚未访问的文件，
共 12 个项目、24 个阶段、240 个任务。使用与前后两版相同的已安装依赖，
Emacs 31.1／Org 9.8.10，源码分别编译后运行。

代表性分阶段测量：原生准备约 121 ms，Sprint 内容生成约 129 ms，最终 finalize 约 6 ms。
准备阶段包含约 100 ms 的 org-load-modules-maybe，主要是 Org 第一次加载链接扩展；
源文件准备的其余成本约 20 ms。内容生成内约 109 ms 位于 org-element-cache-map，
其中包含调用方的任务判断／结果构造。以上是包含子调用的时间，不能重复相加。
Org 原生模块初始化通常在整个会话里只发生一次，未必等到第一次 Sprint 才发生。

只读核对真实会话时，四个 Agenda 文件均已访问、跨刷新缓存接口已加载。
因此没有把隔离 profile 的全部初始化成本当作当前桌面每次打开 Sprint 的延迟。
真实会话只读取版本／源 buffer 状态，没有为计时重载代码或更改窗口。

## 保留的三个改动

1. projects--next 原来收集完整项目的所有候选，最后只取首个活跃候选或首个后备项。
   现在一旦找到首个活跃候选就返回；在此之前只保留第一个后备项。日期、关闭分支、
   习惯、任务叶子和活跃祖先的准入规则不变，也保留调用前 point。
2. 随时读取收满四项后，以原生 org-map-continue-from 跳到当前项目子树末尾。
   原来只停止填充列表，Org 扫描器仍为剩余标题准备标签／类别并调用回调。
3. completed-arranged 复用已有完成回顾的 CLOSED 日期预筛选。没有当天完成记录时，
   不启动完整 Org 扫描；预筛选仍读取已访问 buffer 的未保存文本，匹配项仍由 Org 核实。

生产实现只涉及三个已有读取函数，净增加约 13 行。没有新增缓存、依赖、hook、advice、
计时器、用户选项或预加载。缓存有效性、CLOCK 统计和用户源编辑行为沿原规则。

## 未保留的方向

临时设置原生 org-agenda-inhibit-startup=t 没有测得收益：启动折叠耗时不足 0.1 ms，
模块加载仍发生。没有写入配置，以免为无收益的设置改变源 buffer 初始可见性。
提前 require 链接模块只会转移成本，删减 org-modules 会影响现有链接能力，均未采用。
未通过更大的缓存、合并所有扫描的框架或新的异步机制追逐剩余成本。

## 前后对比与验证

每种条件各运行 5 个全新进程，交替执行基线与修改版；每个进程首次打开后再 redo 五次。
表中首次打开是五次中位数，刷新是对应 25 次的中位数，保留正常 GC。

| 条件 | 基线 | 修改后 | 减少 |
| --- | ---: | ---: | ---: |
| Org 模块尚未加载，首次打开 | 264.86 ms | 244.79 ms | 7.6% |
| Org 模块已加载、源文件尚未访问，首次打开 | 160.39 ms | 141.37 ms | 11.9% |
| 冷启动组的后续刷新 | 59.09 ms | 55.12 ms | 6.7% |

模块已加载的条件在计时前调用原生 org-load-modules-maybe，仅用于区分场景，
没有作为产品改动。两组条件中所有前后输出文本归一化临时文件名后 SHA-256 相同：
2f9d5b63f291deb18e952369a7975073f3fe73ba0030e3351abc8a2910f515b0。
这是批处理原生入口测量，不包括实际 GUI 字体、宿主文件 hooks 和鼠标交互验收。

新增四项回归：首个活跃项确定后不再构造后续候选、无活跃任务保留首个后备项、
四项随时任务读满后停止回调、没有当天 CLOSED 时不扫描完成项。
修改前三个效率断言失败，修改后通过。官方全套 ERT 836/836，通过且无排除；
编译通过，checkdoc 0 警告。现有完成统计、项目进度、源顺序和未保存编辑测试均保留。
