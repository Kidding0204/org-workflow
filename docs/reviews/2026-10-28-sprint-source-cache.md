# Sprint 源事实跨刷新复用

基线为 0ab45b8。用户要求源 buffer 未变时跨刷新复用，并正确识别未保存编辑。
本次没有改写真实 Org、数据库或历史；父配置的既有修改保留。

## 缓存边界与依赖

继续保留单次渲染的文件归属快照与完整项目模型；增加源 buffer 所有的纯事实缓存。
没有源修改 hook、定时器、advice、持久磁盘缓存或新依赖。

| 结果 | 复用条件 | 每次读取的部分 |
| --- | --- | --- |
| 文件项目结构、下一步 | 文本版本、Org 解析设置、文件身份／归属、任务类型、今天日期相同 | Area 暂停状态从数据库新取 |
| 项目与阶段进度、任务位置 | 文本版本、Org 解析设置、文件身份／归属、任务类型相同 | 展开状态和样式仍在渲染时决定 |
| 每项目四个随时任务位置 | 同上 | 每次重新构造任务项与原生 Agenda marker |

`org-workflow-source-cached-read` 的版本使用 `buffer-chars-modified-tick`，不用
`buffer-modified-p` 或磁盘 mtime。继续编辑已修改的 buffer 仍会递增计数，因此
每次未保存编辑都能被识别。间接 buffer 编辑同样改变共享文本版本。
文本属性高亮和只保存不改字，不需要重新扫描。原生 revert、undo、refile、CLOCK
文本写入、插入／删除均会触发该文件的下一次计算，未变的其他文件继续复用。

版本还包含文件名和 Org 的 TODO／完成关键词、标题解析与属性继承设置；读依赖
包含实际文件归属、真实路径与 Workflow 任务类型。当天变化只重算需要日期的下一步模型，
不会凭日期缓存运行中的 CLOCK 或责任结果。
一个 key 只保存最近的 context，不按每个日期追加；新文本版本丢弃旧位置，
避免删除／移动后复用旧来源。缓存返回独立的 cons 树，调用方整理列表不会污染缓存。

只读源函数仍优先读取已访问 buffer，包括未保存内容。未访问文件仍使用原来的
临时读取策略；临时 buffer 结束不会留下缓存，后续磁盘读取不会被旧数据替代。
已访问 buffer 依照原生访问／revert 规则更新，不主动覆盖未保存内容。
关闭源 buffer 会释放缓存；停用 Workflow 也清空缓存。被中断的读取不会存入失败结果。

## 验证与测量

新增 10 项回归。先观察重复刷新、只编辑一个文件、字体属性／保存三个性能断言失败，
再实现缓存。另验证未保存进度、间接编辑、源关闭后磁盘修改、日期与任务类型改变、
数据库暂停状态变化、返回列表隔离、marker 重新创建和停用释放。
marker 测试曾错误地在 redo 后比较旧 marker；Org 原生会清理旧 Agenda marker。
已改为事先保存源 buffer／位置，验证新 marker 指向原位置且不是旧对象，没有修改生产行为。
最终官方全套 ERT 832/832 通过，无排除项；编译通过，checkdoc 0 警告，
全新安装、惰性 require、模式启用／停用 smoke 通过。

沿用前次隔离原生入口基准：4 个文件、12 个项目、24 个阶段、240 个任务，
分别编译基线与本次源码。全新进程通过同一依赖 profile 运行 org-agenda "d"，再 redo 五次。

| 测量 | 单次渲染复用版 | 跨刷新复用版 |
| --- | ---: | ---: |
| 首次打开 | 290 ms | 291 ms |
| 随后五次刷新中位数 | 106 ms | 62 ms |

已有缓存的刷新耗时再减少约 42%；首次打开没有提升，因为尚无可复用源事实。

没有将批处理样本当作图形窗口布局、宿主 hooks 或真实鼠标体验的验证。

## 维护与行动日志

主要入口是 sources 的 source-cached-read；projects 的 read-context 列出领域依赖。
新的缓存读取器只能返回纯值／位置；如果增加数据库或运行时间依赖，应将这些字段
留在缓存外，或显式增加相应 context，不能仅依赖源文本版本。
开发中若重载了读取算法，可执行 `(org-workflow-source--clear-read-caches)` 后刷新。
撤回本次提交可回到仅单次渲染复用。
