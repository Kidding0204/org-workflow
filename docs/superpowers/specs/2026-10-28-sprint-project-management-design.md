# Sprint 项目管理设计

状态：UI 已确认；本设计及实施细节等待确认。确认前只修改方案文档。

## 目标与已确认决定

统一 Sprint 的「今日／明日／项目」入口。项目页用于查看项目与分组、改变项目状态，
并把 Inbox 条目拖到项目或具体分组。使用已确认的双栏 UI：左 Inbox，右项目树。
文件对应 Area，一级 TODO 系列标题对应 Project，二级标题对应 Heading，三级标题对应 Task。
任务的原有细分子标题允许保留；不把捕捉的 QA、想法子节点误当成结构分组或项目。

用户明确确认：任务拖到项目标题时，自动创建／复用该项目直属二级「未分组」，
任务成为其下三级标题。拖到具体 Heading 时，直接移到该 Heading 下。

已确认的交互原型：
`/home/meph1st0/.codex/visualizations/2026/10/28/01a1801b-2287-7d01-aef8-5f25751bc046/sprint-project-management.html`。
原型是交互与布局依据；最终在原生 Org Agenda 中实现，不引入浏览器 UI、CSS 或网页依赖。

## 方案比较与整合选择

- 保留独立项目视图再加一个 Sprint 项目页：会产生两套折叠、选择及操作行为，不采用。
- 把项目树常驻在每日列表末尾：每日执行和结构整理相互挤占，拖放距离过长，不采用。
- 采用 Sprint 三视图：共用一个工作台状态与原生 Agenda 行，项目页使用双栏；旧项目入口转向这里。

不改变原 Org 文件组织，不批量迁移已有标题，不改变既有项目／阶段状态和历史。
一级仍要求现有 TODO/DIVE/HOLD/DONE 项目标识，普通一级笔记和 Inbox 不变成项目。
界面称 Area／项目／分组；不扩大改写存储层中历史 goal 等兼容名称。

## 页面、数据与状态

- 今日／明日保持已有安排、随时和今日已完成规则。项目不带一个独立的安排日期。
- 项目页左栏显示统一 `projects.org` Inbox 的全部未完成任务和 QA，包括已安排和旧条目。
  不受「随时」的未安排筛选或最近七天筛选影响；想法笔记继续留在 Supertag 管理流程。
- 右栏 Area 来自现有 Agenda 文件，文件基础名为标签；顺序沿用文件列表与文件内源顺序。
  Inbox／Someday 等特殊组织标题不识别成项目。空 Area 可折叠，不能当作拖放目标。
- 所有状态的项目都可展开；状态不再决定是否有资格浏览子内容。DONE 默认折叠但可查看。
- 二级普通 Heading 也展示；原有带 TODO/DIVE/HOLD/DONE 状态的阶段保留语义和操作能力。
  不能为了展示或归类把普通 Heading 自动改成 TODO 或 DIVE。
- 三级任务及其细分按源内容展示；普通想法子节点不额外进入任务列表。QA 保留直接 :QA: 标识。
- 项目进度复用现有任务统计／Org cookie，QA 不参与阻塞与完成分母；不维护第二套网页式进度事实。
  无可用统计时不显示 0/0；可以使用已有 cookie 呈现，不强制添加圆形图标或新绘图库。
- 折叠、各视图的光标和滚动位置、两栏宽度属于本 Sprint 实例；切换不影响另一个工作台。
  切换清除跨页批量选择，避免对隐藏条目操作；折叠本身不产生源修改或承诺。

## 拖动归类

### 起点、终点与顺序

首期拖动来源限定为项目页 Inbox。支持单项、Ctrl／Shift 现有批量选择；拖动选中项时
一起移动，没有选中的条目时只移动起拖项。不把父条目及其子节点重复选入。
按 Inbox 显示顺序追加到目标分组尾部，保持批次顺序与原有子树内部顺序。

- 落在 Project 行：查找直属二级标题的干净名称是否为「未分组」，忽略 TODO、标签、优先级等标题修饰。
  没有时在项目末尾建立普通二级「未分组」；只有一个时复用；存在多个同名直属标题时拒绝歧义操作。
  不复用更深层、其他项目或普通任务正文中的同名标题。
- 落在 Heading 行：移动到该二级 Heading，不另建「未分组」。
- 任务行、Area、空白区、其他工作台或外部应用数据不是有效目标；释放或 Esc 取消不会产生修改。
- TODO／DIVE／HOLD 项目和暂停 Area 可以接收归类，不自动启动或恢复；DONE 项目或 DONE 阶段
  不接收新增条目，需要先由用户明确恢复。HOLD 分组可接收条目但继续保持暂停。

### 操作反馈

复用现有 8 像素拖动阈值、选中行与目标高亮、边缘滚动，扩展到项目页两栏。
拖到折叠项目也可归类，成功后展开项目和实际分组并突出新移入的行。
末行反馈归类结果，不在每行新增“拖到这里”等说明。保留已确认原型的“勾选后点击目标名称”
归类：有 Inbox 选择时目标名称点击归类，没有选择时浏览／折叠；箭头始终只折叠／展开。
显示已选数量及可接收目标的鼠标高亮，便于辨认当前操作。键盘提供选择目标的等价归类命令；
双击／RET 访问原文，非目标任务行点击不执行归类。

### 源数据与一致性

移动真实 Org 子树，使用原生 `org-refile` 的标题级别调整，不自行拼接复制／删除，不按标题字符串定位。
保留根节点与后代的正文、链接、附件属性、ID、QA 标签、Supertag 主题、捕捉时间、TODO、
显式 SCHEDULED／DEADLINE／PRIORITY、CLOSED 与 CLOCK。根标题变三级，后代相对层级不变。
Org 的原生祖先标签／优先级继承仍遵循目标位置；不为冻结继承结果额外复制属性。

一次拖动为一个批量事务：先校验全部源及目标，再移动；同文件、跨文件、跨 Area 均走同一路径。
源行必须仍在 Inbox、目标仍为所见项目／分组，并可写、没有文件外部变更。源或目标文件已有
未保存改动时，整批暂不移动，提示先保存这两个参与文件；不顺便保存用户其他编辑。
无 ID 的条目只在已授权移动事务中按需创建身份，显示与刷新不创建 ID。
原生 refile 若调整 undo list 导致 change-group 不足以回滚，应以参与 buffer 的操作前源文本
作为异常还原依据；不能只验证数据库回滚。正常保存继续触发已有 Supertag 等保存钩子，
不直接写第三方索引。事务后修正 Org ID 的文件定位，刷新源 marker 与当前项缓存；正在计时的子树不允许归类，
提示先停止计时，不自动停止或启动。普通当前目标若移入暂停项目而失效，按已有资格规则处理。

复用现有 Org／SQLite operation 与恢复记录，明确列出源／目标参与文件。
原生 refile 的内部自动保存必须在批次期间延迟到事务提交后，不能每移动一项就保存半批。
提交后先保存目标文件、后保存来源；目的地未保存成功时，不能把源删除先写盘。
结果分为三种：提交前失败则整批回滚且不替换原撤销；已提交并保存则正常完成；已提交但保存未完成
则提示「归类已应用，保存未完成」，登记本次归类为最新撤销记录，标为待保存，保留恢复事实。
登记发生在数据库提交且源变更已接受之后、checkpoint／刷新／保存之前，即使这些后处理出错也不会遗留旧撤销。
待保存不是零修改失败：刷新不重放移动，同一源行已离开 Inbox，不能再次执行相同归类。
待保存期间阻止本工作台继续其他源写入，允许重试参与文件保存或按 U 反向撤销；两条路径均通过
operations 恢复与已知文件版本校验，不以“保存成功后才登记撤销”留下记录空档。
不把多文件保存宣称为磁盘上的原子操作；沿用 operations 恢复协议处理部分写盘／中断。

归类不修改显式安排、计时与项目状态，不自动追加／替换当天承诺，也不回算历史归属。
项目状态操作仍使用 `org-workflow-projects-set-state`，按既有规则撤回／恢复责任。

## 撤销

### 唯一入口

沿用 Sprint 的 `U`，名称改为「撤销安排／归类」。每个 Sprint 实例只保留最后一次已应用的
安排或归类记录；跨今日／明日／项目共用。批量归类整体撤销，待保存的已应用归类也可撤销。
本期是单步纠正，不是多级 undo/redo；刷新、切页、折叠和浏览不替换记录。
提交前失败或取消不覆盖上一条记录。旧 `org-workflow-agenda-undo-plan` 保留兼容入口。
项目状态、项目开始日期、Area 暂停／恢复暂不纳入 U：它们经现有 API 执行后清除本工作台旧记录，
并保留失效原因，U 提示最近操作类型，不能悄悄撤销更早归类。状态通过现有状态入口调整；
“恢复 Area”不是承诺完整反转所有历史元数据的通用 undo。
这些 API 会改变暂停批次所有权、延期属性，并可能同步其他项目责任，不能仅反向设置 TODO
就声称完成撤销。本期不扩展这套复杂补偿，避免增加未确认范围。

### 归类撤销的边界

记录参与文件的操作前／后源文本、原始位置与顺序、新建分组、ID 定位、数据库与日期。
撤销前核对参与文件仍等于归类后的版本，磁盘也没有外部冲突，当前数据库和日期未变化。
其后对参与文件的任何编辑（包括新 CLOCK 或 TODO 变化）会拒绝旧快照回滚；不覆盖这些更新。
保存相同文本、刷新与其他文件的编辑不阻止撤销。若检查不通过，明确提示使用原生 refile 手动归回。

校验成功后在反向事务中恢复原文件位置和顺序，只移除本操作创建且仍为空／未改变的「未分组」。
预先存在的分组不删除；ID 定位同步回原文件。保存顺序以本次反向移动的目的地为先。
只纠正这次操作的可变事实；不重放整库快照，不删除 CLOCK、承诺事件或已结算快照。

安排撤销保留现有后续事件校验。归类撤销不回算项目责任，其他状态操作也不能绕过已确认的
当日固定承诺规则。待保存归类反向成功后清除记录；反向保存仍失败时继续显示恢复状态，
不能转而让 U 撤销一个更早操作。
