# Sprint 捕捉、疑问处理与每日承诺实施方案

> 实施者：在本会话使用 superpowers:executing-plans 按任务实施；本文审阅确认前不修改功能。每项先补必要回归测试，再修改原定义、验证和提交。

**目标：** 以 Sprint 为唯一日常处理入口，保留内容的原始归属，低摩擦捕捉任务、疑问和想法；主动安排决定每日承诺。

**架构：** Org 文件保存正文、ID、捕获时间、状态、标签和安排；Workflow 现有事务及数据库保存承诺。Sprint 通过来源 marker 展示和操作原节点，supertag 索引相同 Org 内容，不复制正文或建立另一套处理状态。

**技术：** 现有 Org、org-capture、org-agenda、org-workflow 与已安装 supertag，无新增依赖。

**规格来源：** 本文同时记录本会话已经确认的设计，以及下文明确列出的实施默认值。

## 全局约束

- 保留用户已有修改，父 Emacs 仓库与本包独立提交，不推送。
- 修改现有声明、生命周期和事务入口；不新增用于覆盖冲突的 advice、定时器或高优先级键图。
- 不重启 Emacs；验证后尝试局部加载到运行会话，明确报告未生效或需重启的部分。
- 不用真实 Org/SQLite 数据演练写操作，不自动批量迁移旧 QA/LAB/HW/NOTE 或旧 checkbox 笔记。
- 历史承诺、结算、CLOCK 和已有 ID 保留；旧数据兼容不等于继续提供旧捕捉入口。

## 设计与默认值

### 1. 状态、身份与归属

- 普通任务沿用 TODO/DIVE/DONE/HOLD。新疑问使用 TODO 标题加直接 Org 标签 :QA:，完成后为 DONE，保留 QA 标签、答案与主题。
- 想法是无 TODO 状态的普通标题。删除 QA/LAB/HW/NOTE 的新状态声明与本次相关外观配置，不覆盖文件自身的局部状态定义。
- QA 身份只看节点直接标签，不从父级或文件继承。主题使用 supertag 原生 #主题；默认不启用将全部 Org 标签导入 supertag，避免把 promise、QA 等控制标签混入主题体系。
- 未安排 QA 不执行；有自身 SCHEDULED 的未完成 QA 可以执行。任何 QA 都不使父任务丧失可执行资格，不进入父任务的完成数量与自动推进判断。
- 捕捉及安排 QA 不自动切换当前任务；用户显式启动才切换。投入使用直属 CLOCK，父子不重复计时。

### 2. Capture

- 五个明确叶子入口：任务→Inbox；疑问→当前任务；疑问→Inbox；想法→当前任务；想法→Inbox。
- 菜单建议键位：t、qc、qi、nc、ni；保留 c 作为疑问→当前任务的兼容别名，原 n 改为“想法”分组，避免重复定义。
- 三种 Inbox 捕捉均指向现有 projects 文件的 Inbox 一级标题；不新建另一份 Inbox。网页入口 p/L 和截图入口保留原快捷键，按相同身份规则兼容。
- 当前任务入口创建其直接子标题；没有当前任务则明确提示选择相应 Inbox 入口，不静默转存。
- 入口采用 entry capture；自动生成 ID 和 CAPTURED_ON（保留现有字段，新增条目写本地日期与时间），保存可用的来源链接和选区。标题为任务描述、问题或想法，正文自由填写，不强制标签或额外表单。
- 不再由 core、inbox、宿主 supertag 配置分别安装重叠模板。包集中声明模板；宿主负责路径与个人绑定。
- capture 的完成、中止和窗口关闭沿用现有机制；成功完成启用 supertag 索引，中止不得残留节点。

### 3. Supertag

- 继续使用原有 ID、#标签、主题 Stream、关联发现和节点编辑能力，不开发替代界面，不增加整理状态或定时复习。
- 保留当前 etc/notes 同步范围，增加实际 Workflow Org 根目录 ~/Dropbox/org/，覆盖 notes、projects.org 和兼容 inbox.org。不搬移原文件。
- NOTE 不再是状态或 supertag 准入条件；QA、DONE QA、普通想法均可索引。无主题的笔记也可保存，之后随时添加主题。
- 目标模板使用 :supertag t；索引及重扫仅使用公开入口，不直接编辑 supertag 数据库。配置范围变更使用已有公开机制，不能安全现场应用则留待下次启动，不自动重启。

### 4. Sprint

- 上方保留安排区和今日/明日切换；下方“收集箱”改名“随时”。既有非时段习惯保留。
- 随时中的顺序：既有自由习惯；Inbox；疑问；各 DIVE 项目的未安排任务。Inbox 内 QA 只出现一次；疑问组补充保存在任务下的未安排 QA。
- 未完成且无自身 SCHEDULED 的 QA 跨日期保留，按捕获时间从旧到新，缺失时间排最后并沿用来源顺序；显示标题、归属及可展开的正文，不能只剩链接而要求反复切换。
- 普通无状态想法和 DONE QA 不出现在随时；已安排 QA 只进入其日期的安排区，逾期沿用现有逾期显示规则。
- 今日/明日切换只改变安排区，随时仍是当前可处理内容。不新增日回顾主视图或专用 mode；既有独立收集回顾入口改为打开 Sprint 的相应区段，消除重复界面的维护。
- 原文编辑复用 Org/Agenda 来源访问，在同一窗口显示来源子树，完成后返回原 Sprint 的光标和滚动位置；不在聚合 buffer 中同步编辑正文。
- 每个 DIVE 项目按源文件顺序取前四个未完成、未安排的普通可执行任务；每项目合计四个，按项目、阶段分组。排除 QA、习惯、项目/阶段标题、暂停或阻塞分支；SCHEDULED 在过去或未来都不属于未安排。
- 移除承诺任务下原有的动态 1–3 项后继预览，只在随时展示四项。保留任务 marker、批量安排、查看和启动能力，不在渲染过程中写状态或承诺。
- 不另加一套每日工作事件持久化；当天完成和投入继续复用现有安排与历史事实，普通想法不参与每日待办处理。

### 5. 每日承诺

- 对每个可运行且处于 DIVE 的项目，取自身 SCHEDULED 日期等于当天的未完成可执行任务，严格依源文件顺序选首项。已安排 QA 同样可选，习惯及阻塞分支不可选。
- 不根据优先级、时段、活跃阶段或安排操作顺序改变选择。不选逾期任务，不从无安排任务补选，不自动补写 SCHEDULED。
- 晚间安排明天不创建正式自动承诺；复用现有换日/启动/同步入口，在当天首次有候选时生成。休眠或未运行的过去日期不补造承诺；渲染只读。
- 复用现有 project-day 日期/项目持久索引，跨刷新与重启固定当天首个承诺。完成、改期、重排、新增安排不追加也不替换。
- 手动操作优先。扩展原承诺命令支持更换当天项目承诺和显式撤回：更换使用同一事务结束旧责任、关联新责任、更新当天索引；历史事件保留，不能同时留下两份有效项目责任。撤回后保留当天已作决定的记录，禁止自动补选或恢复。
- 上线当天已有项目责任也视为已确定，不重选；既有未来手工承诺与当天候选同任务时复用，不重复创建。暂停/恢复延续既有显式语义，不静默替换候选；过去结算不重写。

## 审阅重点

1. QA 虽是物理子标题，但不能让父任务被替换或自动完成。
2. 明日投影不得写明日正式责任，跨日后仅创建一次。
3. 手动撤回或更换不能被后台同步反转；异常时事务不能留下双责任。
4. 想法即使存入 Inbox 也不应被当成待办；无安排 QA 不能遗漏或重复。
5. Capture 中止、现场未保存文字、不同同步目录及旧状态文件不能丢失数据。

以上重点分别由任务一至四的回归及任务五的现场检查覆盖。此方案不包含自动语义分类、旧笔记批量迁移、新时间线数据库、新主视图或 supertag 替代实现。
