# 捕捉、疑问与随时

Sprint 是安排和收集处理的统一入口；原节点保留在所属任务或 projects 文件的 Inbox。

## 捕捉

| 键 | 内容 | 去向 |
| --- | --- | --- |
| t | TODO 任务 | Inbox |
| qc / qi | TODO 疑问，直接标签 :QA: | 当前任务 / Inbox |
| nc / ni | 无状态想法 | 当前任务 / Inbox |

c 与 qc 相同，p/L 网页和 S 截图入口继续可用。所有新任务、疑问、想法都有 ID、
CAPTURED_ON 本地时间及可用的上下文链接。主题不强制填写。
当前任务入口没有可用对象时提示改选 Inbox，不隐式转存。

QA 的物理归属不是前置依赖。没有自身 SCHEDULED 时只进入待处理区；有安排时可
独立执行，但始终不使父任务失去可执行资格，也不计入父任务的自动完成统计。
捕捉或安排不会抢占当前任务。解答写在同一节点，完成为 DONE，QA 标签保留。
Inbox 自动归档会保留 QA 及含已标识想法的完成任务，避免长期笔记被归档流隐藏。
想法与已完成问答由可选 Supertag 的 #主题、主题流和关联能力长期组织；
不要求 NOTE 状态，也不把 Workflow 控制标签当主题导入。

## 随时

安排区保留时段和今日／明日切换。随时区先显示自由习惯、Inbox，再显示任务下的
未安排疑问，最后按项目、阶段展示 DIVE 项目的前四项未安排任务（每项目共四项）。
暂停、阻塞、完成、习惯、项目/阶段标题和 QA 不占四个名额；任何日期的 SCHEDULED
均视为已安排。普通想法即使在 Inbox 也不进入待办视图。

随时中的项目标题与其他类别同样式，用斜体区分项目。完成的任务集中在底部“今日已完成”，
不再留在原时段；每个完成项只显示当天直属 CLOCK，不显示累计时间。
当某时段的任务全部完成后，正文显示完成数量和当天直属 CLOCK 总时长；
仍有待办时保留任务列表，没有完成记录的空时段显示“暂无安排”。明天视图不带今日完成栏或总结。

未安排 QA 跨天保留，按捕获时间由旧到新；缺失时间排后并保持源顺序。Inbox QA
只显示一次；有安排后只在安排区出现。切换明天只改变安排区，随时继续显示当前
可处理内容。独立收集回顾命令现在定位到 Sprint 的随时区。

疑问行 TAB 展开/折叠正文，e 在同窗口打开来源子树的间接缓冲区。
间接缓冲区与原文件共享文字，不是副本；C-c C-c 保存并返回原 Sprint 位置。
修改包的 org-workflow-agenda-notes.el 可调整回顾/编辑交互，
org-workflow-agenda-view.el 决定区块顺序。

## 每日承诺

当日同步对每个可运行 DIVE 项目按源顺序选择首个明确安排在当天的未完成任务，
已安排 QA 同样可选。不按优先级、时段或安排操作顺序选择；没有当天安排就没有
自动承诺，不自动为未安排任务补日期，也不把逾期任务选为新一天承诺。

晚上安排明天只修改安排。换日后或当天首次有候选时自动确定，日期/项目索引把
决定固定下来，刷新和重启不重选，完成不追加。改期、重排、新增安排不替换。
在另一条当天已安排任务上按 p 手动更换；在有效承诺上按 p 撤回。
手动操作保留历史，并阻止后台同步补选。已有当日责任不因升级重选，过去结算不变。
项目暂停/恢复继续作用于原责任，不换另一项。

维护入口：org-workflow-projects.el 的每日同步与 org-workflow-commands.el 的手动
承诺命令；不要在渲染代码中生成承诺。宿主仅负责路径、绑定和可选 Supertag 配置。

## 验证与恢复

针对性 ERT 位于 test/org-workflow-sprint-capture-test.el，并与现有项目、收集、
工作台和历史测试配合。测试使用临时 Org/SQLite，不操作真实任务。
图形验收：五入口各捕捉一次；验证当前任务不被 QA 替换、随时分组/展开/编辑返回；
安排并完成 QA 后，从主题流找到原 ID；手动更换或撤回后刷新仍保持决定。

旧 QA/LAB/HW/NOTE 标题及 checkbox 不批量转换；有局部 TODO 声明的文件保留原义。
恢复代码使用本次 Git 提交的 revert，保留 Org、SQLite、Supertag 数据；不要删库回退。
