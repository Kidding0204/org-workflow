# 习惯与重复事项：长期上下文

更新：2026-10-09。后续会话修改习惯系统时先读本页，并同步实际规则与验证结果。

## 设计意图

以个人日常使用的简单原型为目标，先使用，再按明确需求调整。习惯的定义尚在探索；
此入口承载希望培养／维持的行为，以及周日回顾这类例行事项，不用软件判定是否已自动化。
完成表示一次行动达到用户定义的标准，不等于形成习惯。周进度与连续天数也不等于自动化程度。

每次完成标准写在标题或正文；提示情境（例如饭后）可写在正文，目前不自动识别生活事件。
一周统一为周日至周六。该约定用于习惯轨迹与周次数，不改写历史工时或承诺事实。

## 当前重复安排

入口：新增习惯会询问重复方式；已有习惯用 `M-x org-workflow-habits-configure-repeat`。
Sprint 中 `C-c r` 或右键「重复安排」；`C-c h` 继续设置时段／提醒。

| 模式 | 语义 | 例子 |
| --- | --- | --- |
| 完成后间隔 | 完成日期加 n 个日历日；到期未完成保持待做 | 做完后隔两天 |
| 固定星期 | 选择一个或多个星期；晚完成不改变星期节奏；非指定日不主动呈现未完成项 | 每周日整理阶段日记与安排 |
| 每周次数 | 周日至周六完成 n 次，1–7；每天最多计一次；达标后停止主动呈现，完成当天仍保留 | 每周阅读《原子习惯》三次，每次一章 |

周次数完成后仍是 TODO；多次 CLOCK 不自动增加次数。未达标不累计到下周。
同一天重复完成或本周已达标时拒绝再次完成。当前一天最多一次是首版限制；如实际需要
同日多次阅读，再调整完成次数、当天状态与提醒的共同语义，不只放宽按钮。

首次日期控制开始；修改规则以选定首次日期重新安排。完成日志和 CLOCK 保留。
原有习惯无新增属性时沿用原生 Org 重复，不自动迁移或重写。

## 源码与存储

- `org-workflow-habits.el`：规则配置、周日起点、完成日计数、当天项读取。
- `org-workflow-items.el`：共用完成操作；周次数校验与固定星期推进。
- `org-workflow-evening.el`：规则／周进度和日—六轨迹；非执行日中性显示。
- `org-workflow-panel.el`：复用当天项，因此达标和非执行日也影响桌面提醒。
- `WORKFLOW_HABIT_WEEK_TARGET`：周次数；`WORKFLOW_HABIT_WEEKDAYS`：0–6，0 周日，逗号分隔。
- 原生 `STYLE: habit`、`SCHEDULED` repeater 与 LOGBOOK 仍为来源。固定星期使用 `++1d`
  并在原生重复 hook／共用完成操作后推进到下个指定星期；周次数使用 `.+1d`。
- Workflow 启用时，原生 Org TODO 完成也会通过 repeat hook 修正固定星期。
  每周次数展示从日志按完成日去重计数；Workflow 完成入口还会拒绝重复／超额完成。
- 不新增数据库表，不按当前规则倒推过去达标，不改已结算历史。

## 阶段目标的边界

“到某日期达到某进度”是独立阶段目标，使用原生 TODO + DEADLINE，不设 STYLE habit。
父任务可用 Org 原生子任务／检查列表统计表达进度；系统不自动计算抽象项目百分比。

Sprint「阶段目标 · 截止日期」在头部展示 project/area Agenda 来源中有 DEADLINE 的 TODO，
按日期排序，标注逾期和今天截止。排除 DONE、HOLD 子树、习惯、封存来源；不要求父级 DIVE。
仅 DEADLINE 不进入当天执行队列；需要实际工作时，另安排具体执行任务。
本区也会呈现普通截止任务，首版不新增目标标签来区分。

## 暂不实现与后续观察

不增加复杂月／年规则、自动章节计数、暂停／恢复、仅修改本次安排或补做债务系统。
已有原生 Org 规则仍可手动使用。重点观察：

- 周次数每天最多一次是否适合真实阅读。
- 固定星期漏做后不持续展示是否合适。
- 周次数默认沿用现有时段每日提醒是否打扰。
- 阶段目标是否太多，是否需要显示范围与项目上下文。

新需求由实际使用提出；记录决定和原因，不把这里变成预设的功能路线图。

## 验证

自动测试使用临时 Org／SQLite；覆盖真实完成日志、间隔推进、固定星期延迟完成、
多星期选择、周六／周日重置、达标隐藏、同日重复拒绝、未来首次日期、规则切换保留事实，
以及截止目标排序、排除、原生 marker 和 TODO 操作。
具体本轮结果见 `verification.md`。自动测试与 GUI 检查分开记录。
