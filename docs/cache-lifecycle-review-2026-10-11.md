## 已修复

1. 完成和归档在 `org-element-use-cache=nil` 下修改文本，Org 的缓存修改钩子
   跳过更新。暖缓存中 TODO 或日程会与正文不一致。移除写入路径的禁用绑定。
2. 刷新、选择和习惯读取的禁用范围覆盖文件访问及回调，可能连带影响用户钩子中
   的修改。禁用范围缩到访问后的只读扫描；evening 和 current-item 不再包住整条调用链。
3. 生命周期无条件认领已存在 hook，停用会删除用户的注册。现在只记录新增项，
   并遵循原生 add-hook 的局部性规则，在正确 buffer 中撤销。
4. panel 展示缓存与习惯 marker 跨模式启停保留。现在启用使缓存失效，停用释放
   快照和 marker；删除无生产读取者的 current-item-cache。
5. 无初始值的共享 defvar 声明编译后不留运行时声明。部分 Sprint 筛选／布局的
   let 因此被编译成无效的词法绑定，归档的延后保存开关也因仅在函数内 require
   而丢失动态绑定。修复实际使用处的声明，将 org-archive 依赖移到编译可见的顶层。
   删除无实际跨文件作用的 declarations 库；构建先暂存全部源码，优先加载暂存版本，
   避开宿主旧字节码。
6. 删除存储解码中不起作用的 read-eval 词法绑定；仍使用原有 Emacs Lisp read，
   不改变序列化格式或数据库内容。

保留 source-read 的现场未保存内容、point/narrowing 保护和临时只读 buffer。
保留只读扫描的局部缓存绕过，避免重新引入后台解析卡顿。
不引入全局缓存开关、通用重试层或额外状态框架。

历史测试数量不是后续验证保证。

## 保留的限制

无 ID 条目的提醒键由文件与标题生成，同文件同名的手写习惯可能冲突。包的习惯创建
入口会创建 Org ID；后台只读查询不会补 ID。此处不改持久提醒身份，不用会随编辑
漂移的位置代替稳定 ID。手写同名习惯应使用原生 Org ID；后续如支持无 ID 重名数据，
须单独定义已有 sent/skipped/current 状态的迁移规则。

本轮不声称已完成 GUI、桌面或所有业务语义的穷尽验证，也不自动重新加载运行中的
计时与恢复状态。
