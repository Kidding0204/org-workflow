# 请假条

[文档入口](README.md)（文中的默认快捷键需设置 `org-workflow-install-default-bindings` 为 t） · [任务与历史模型](workflow-architecture.md)

运行 `M-x org-workflow-record-leave`，选择今天的时段（上午、下午、晚上、组合或全天），填写一行理由。

昨天有未完成承诺且没有任何请假记录时，启动 Emacs 会直接要求补录昨天的时段和非空原因。后台 daemon 不弹提示，首次普通客户端窗口打开后再填写；跨日重新聚焦现有窗口也检查。同一天已检查通过后不重复提示，已有原因、全部完成或没有承诺时不提示。取消输入不会写入或解除要求，下次打开仍会检查。只检查昨天，不批量追问更早日期。

也可用 `C-u M-x org-workflow-record-leave` 主动补录历史日期。历史补录使用当天结算中的未完成承诺快照，不因今天补做、延期或改名而变化；旧历史没有可靠时段信息，任务列为「时段未记录」，不推断属于哪个时段。请假条写回该日期所属周的随记，GNOME 和历史导出同步读取，不重算已结算工时或完成结果。

记录写入本周日志「随记」，并保存到 Workflow 数据库。涉及任务是记录当时所选时段内的所有未完成执行任务，包括今日栏中的逾期任务；不受 Sprint 的分组或标签筛选限制。习惯不在其中。没有任务时也可以记录当天活动。

它不改安排、TODO、承诺或计时，也不计为工作投入。GNOME 本周状态在无投入但有记录时显示请假；已有投入时保留投入状态，说明中同时显示请假时段和理由。数据不可用仍显示未知，不用请假掩盖读取错误。

长期回顾的日期标记和详情显示时段、理由及任务标题快照。历史页面仍只展示已结束日期，今天的记录在次日结算后出现。后续重算工时保留请假条，任务之后完成或改名不改变原记录。

一个命令完成一次记录，可为同一天的不同事件重复记录。输入取消或校验失败不写入；数据库失败回滚随记编辑。周日志保存失败时保留数据库与恢复记录，并报告错误。保存也会包含该周日志中已有的未保存编辑，不保存其他任务文件。
