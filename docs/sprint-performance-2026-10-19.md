# Sprint 打开延迟诊断

日期：2026-10-19。前文记录最初诊断与临时实验，末节记录用户确认后的实际实施。

## 结论与实施顺序

1. 优先恢复当前 Org 9.8.10 的编译产物，再重新加载／重启后验证真实快捷键。
   运行中的 Workflow 热点已原生编译，但 `org-map-entries`、
   `org-element-cache-map`、`org-entry-get-with-inheritance`、
   `org-back-to-heading` 都是解释执行，安装目录缺少 `org.elc` 和
   `org-element.elc`。临时副本编译实验确认这会显著放大扫描成本。
   没有追溯缺失产物的安装历史，不能据此认定是哪次操作造成。
2. 可选的后续小改动：在一次 `org-workflow-agenda-workbench-view` 渲染中，
   让安排区与可选区共用同一日期的 habit rows。当前两区分别调用
   `org-workflow-evening--habit-rows`，会重复扫描同一组来源。
   复用范围必须止于本次渲染，不能跨刷新缓存或隐藏未保存编辑。
3. 编译恢复后再决定是否合并其他扫描。暂不重写原生任务筛选，不全局关闭
   Org cache，也不为此引入持久缓存或提高全局 GC 阈值。

## 运行中 Emacs 的测量

环境：Emacs 31.1，Org 9.8.10；6 个 Agenda 来源，合计约 30 KB，
测量开始时均已访问且没有未保存修改。使用临时 Agenda buffer，保留调用者窗口。
只记录耗时与函数计数，不在报告中保存任务正文。

- 闲置状态直接经 emacsclient 调用：三次为 1.061 / 1.026 / 1.041 秒，
  各触发 6 次 GC，GC 占 0.649–0.671 秒。
- 这组数据不能当作真实键盘延迟：当前 GCMH 在 `pre-command-hook` 中提高阈值，
  emacsclient 不经过该 hook。以既有 128 MiB 交互阈值局部绑定重测，
  三次为 0.380 / 0.524 / 0.531 秒，其中后两次各有约 0.140 秒 GC。
  桌面 Workflow dispatch 已有相同阈值保护，不应再重复添加全局 GC 设置。
- 一次打开共有 37 次 `org-map-entries` / `org-element-cache-map` 调用。
  习惯扫描执行两遍；目标、队列、已完成时段和候选也分别扫描来源。
- `org-agenda-finalize` 约 5–7 ms，`org-modern-agenda` 约 0.4–1 ms；
  数据读取／属性查询是当前更值得优化的路径。

## Org 编译前后对照

把当前来源的只读快照放到权限为 0700 的临时目录，在独立 `emacs -Q --batch`
中测试。两组均加载同一份 Workflow 字节码、同版本 Org 源码、同一组任务快照，
使用 128 MiB GC 阈值。只在临时 Org 副本中生成字节码，未修改宿主 ELPA。

每组首次渲染一次，再连续渲染五次。首次渲染包含首次访问来源和建立缓存，
不包含 Emacs 启动／require 包本身的时间。

| 方案 | 首次渲染 | 后五次中位数 | 后五次范围 |
| --- | ---: | ---: | ---: |
| 当前解释执行 Org | 559.6 ms | 379.9 ms | 322.5–393.3 ms |
| 临时副本编译 Org | 228.4 ms | 73.4 ms | 72.3–74.4 ms |
| 编译 Org，并在一次渲染中复用 habit rows | 222.7 ms | 62.9 ms | 62.4–64.2 ms |

编译后的重复打开中位耗时减少约 81%，首次渲染减少约 59%。三组渲染文本的
SHA-256 一致。这是隔离基准的结果，不代表真实图形快捷键已经达到相同延迟。

## 习惯复用的单独验证

也在运行中的 Emacs 做了临时函数替换实验，结束后恢复原始定义。

- 每次渲染的 habit source 扫描由两遍降至一遍，Org 扫描由 37 次降至 31 次。
- 对照三次与实验三次的渲染文本哈希一致。
- 当前解释执行环境下，扣除 GC 的计算中位耗时约从 339 ms 降至 304 ms。
  原始墙钟耗时受 GC 发生在哪次测量影响，不能据此宣称稳定降低同等延迟。
- 在已编译 Org 的隔离基准中，额外节省约 10.5 ms，收益小于恢复 Org 编译。

## 后续验收边界

恢复编译产物后，需要确认新进程加载的是编译后的同版本 Org，而非仍驻留的旧定义，
再从实际键盘／桌面入口测一次首次打开和重复打开。编译本身不会替换已加载函数。

若实施 habit rows 复用，需要用临时数据验证今天／明天、自由习惯／定时习惯、
习惯完成／重复以及两次刷新之间的未保存修改，保留原生 marker 和操作后位置规则。

本次结束时，临时替换的 Workflow 函数已恢复，6 个实际来源 buffer 的 modified
标志仍全部为 nil。未运行计时、完成、安排或归档操作。个人数据快照不纳入 Git。


## 确认后的实施

用户确认执行后，已完成两项修改：

- 使用当前 Emacs 31.1 为实际安装的 Org 9.8.10 生成字节码：127 个文件编译成功，
  4 个不需要编译的文件跳过。没有升级 Org 或改写其源码。
  独立新进程确认 `org-map-entries` 和 `org-element-cache-map` 从实际安装的
  `org.elc`／`org-element.elc` 加载，且均为字节编译函数。
- `org-workflow-agenda-workbench-view` 每次渲染读取一次 habit rows，显式传给
  安排区与可选区。可选区独立调用时仍能自行读取；显式传入 nil 代表已读到空列表，
  不重复扫描。明天视图不读取习惯，没有跨渲染状态或持久缓存。
  实际包目录中的 Sprint 视图字节码也已更新。

新增临时 Org 回归验证：有／无习惯时每次渲染只扫描一次；今天／明天切换；
自由／定时习惯分区；原生重复完成后的下次日程；未保存标题在下次刷新可见。
完整测试 648/648 通过，Workflow 自身编译零警告（保留 7 条第三方过时宏警告）。

实际安装加新实现的独立进程复测：首次渲染 225.8 ms，后五次中位数 62.9 ms，
范围 60.9–63.7 ms。来源快照与最初基准一致，渲染文本 SHA-256 也一致。
所有临时个人数据快照在测量后删除。

没有热替换运行中的 Org 或自动重启 Emacs。字节码生成不会改变既有进程中的旧定义；
用户重启后仍需从真实键盘／桌面入口确认响应速度。这是剩余的交互验收边界。
