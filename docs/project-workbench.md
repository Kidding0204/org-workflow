# 项目规划与每日推进

[文档入口](README.md) · [任务与历史模型](workflow-architecture.md)

项目视图管理长期目标下的学习项目，今日 Sprint 继续按上午／下午／晚上安排。
本次不改变今日视图的布局，也不加入后续步骤预览。

## 打开与操作

`M-x org-workflow-project-view`，或 Workflow 菜单 `p`，或 Sprint `P`。
视图只读；刷新不会生成承诺、创建 ID 或保存源文件。

| 按键 | 操作 |
| --- | --- |
| RET | 打开该项目／目标的原 Org 标题 |
| TAB | 展开／折叠目标或项目规划 |
| t | 设置项目状态；在目标上批量暂停／恢复 |
| s / C-u s | 安排／清除 TODO 项目的开始日期 |
| G | 修改项目所属长期目标，支持跨文件 |
| n | 打开已有 Agenda 源文件，准备登记标题 |
| D | 显示／收起已完成项目 |
| g | 只读刷新 |
| R | 显式同步手工直接编辑的源文件，再刷新 |
| a / q | 打开今日／返回 |

DIVE 项目默认显示当前阶段和下一步；TODO、HOLD 默认紧凑，DONE 默认收起。
下一步是项目规划信息，不是当天承诺标记。没有可执行步骤时显示“尚未明确下一步”。
长标题按窗口自然换行；状态分组没有重复中文标签或完成百分比。

## 首次登记

原有 DIVE 标题可能是章节或任务组，不能自动当成项目。程序不会迁移真实课程文件。
在已加入 `org-agenda-files` 且带 `project` / `area` 文件标签的 Org 文件中：

1. 在长期目标标题上调用 `M-x org-workflow-projects-register`，选择“长期目标”。
2. 在课程／材料／实践的根标题上调用同一命令，选择“项目”。
3. 项目在目标子树下会自动归属；跨文件项目可在登记时选择目标，或在项目视图按 G。
4. 在项目视图按 t 选择 DIVE，即开始每日推进。原 Org 编辑仍由用户正常保存。

最小结构如下（ID 由登记命令生成，不需要手填）：

```org
#+filetags: :project:
* 成为 AI Compiler 工程师
:PROPERTIES:
:WORKFLOW_KIND: goal
:ID: example-goal
:END:
** DIVE 编译原理
:PROPERTIES:
:WORKFLOW_KIND: project
:ID: example-compiler
:END:
*** DIVE 词法分析
**** TODO 实现简单词法器
**** TODO 补充边界测试
** TODO MLIR 实践
:PROPERTIES:
:WORKFLOW_KIND: project
:ID: example-mlir
:END:
*** TODO 搭建实验环境
```

跨文件归属使用项目的 `WORKFLOW_GOAL_ID` 引用目标 ID。项目结构、说明、步骤、CLOCK
仍保留在原 Org 中；没有第二份计划数据库。不要手工复制示例 ID 到多个真实标题。

## 状态、开始日期与承诺

- TODO：尚未开始；SCHEDULED 表示计划开始日期，不下放给全部步骤。
- DIVE：每天推进，不需要项目有 SCHEDULED；一天冻结一份承诺。
- HOLD：立即暂停，撤回当天未完成承诺；已完成和全部已记录 CLOCK 保留。
- DONE：项目完成，不再产生新承诺。

启动／午夜补处理、项目登记、原生状态／日期操作会同步今日承诺；直接手改标题文字
或属性后可以按 R 同步。系统不会给关闭 Emacs 的过去日期虚构承诺。

系统从当前推进分支选择第一个可执行未完成叶子，优先 DIVE 分支；排除 HOLD／DONE
子树、未来已安排步骤、习惯、QA/LAB/HW 类型节点，以及属于另一个已登记项目的子树。
类型节点下面真正的 TODO 后代仍可执行。明确项目根本身不会作为执行步骤入队。

当天完成后不追加新承诺。未完成步骤下一天继续承担当天责任，不累积重复欠账；
今天完成不会把昨天改写为完成。已有同日手动承诺会接管复用；旧逾期承诺通过带日期
的接管事件停止继续累积，原日期和过去结算不改。

批量暂停只记录当时 DIVE 的项目。恢复只恢复仍属于该暂停批次的 HOLD 项目，原有
TODO/HOLD 不动；期间手动改变状态或归属会取消批次资格。恢复当天已完成的项目不
新增承诺，同日未完成承诺复用原记录。暂停期间错过开始日期的 TODO 保持 TODO，并
显示“待重排”；重新设置开始日期或手动切换 DIVE 后才启动。

## 当天底线

新规则从升级后首次启用的日期生效：完成当天全部有效承诺，或者达到全天最低投入。
承诺本身恢复为完成语义，尝试不等于完成。全部撤回或空集合不算自动成功。

`org-workflow-daily-minimum-minutes` 默认 60 分钟，可通过 Workflow 设置调整。
这是可调整的实现默认值。首次使用某一天时保存该日门槛，修改设置从下一个未记录
日期生效，不回写过去标准。累计所有普通任务及习惯的已结束直接 CLOCK；正在运行的
计时仍由原计时器显示，结束后计入每日底线。Focus Timer 的短区间取消规则保持原样。

顶栏显示“承诺完成数／总数 · 投入／门槛”，任一条件达到就满足底线。历史同时保存
承诺完成情况、整体投入与底线达成依据；原有承诺连续天数仍只统计承诺，不伪装成
时间达标连续天数。日详情先呈现任务进展，投入作为辅助信息。

Org 与 SQLite 写入使用现有事务及恢复机制；不自动保存无关编辑。旧历史快照保持
原样，旧日期继续使用当时的尝试规则，暂停／恢复也不会删除已记录投入。

## 运行环境验收

升级源码后正常重启 Emacs／daemon，使新模块与模式生命周期加载。无需清理数据库。
GNOME 配套源码需要按扩展安装流程更新并在新 Shell 会话中加载；本次不自动注销用户
或覆盖已安装扩展。旧版扩展仍能读取原字段，但不会显示新增时间底线。

实际字体、窄窗口换行、键盘手感与顶栏宽度需要现场试用。本次自动化验收使用临时
Org／SQLite 数据，未改变个人学习文件或线上持久事实。
